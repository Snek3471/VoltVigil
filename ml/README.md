# VoltVigil ML Service

Fault severity prediction microservice for VoltVigil. Uses a trained `RandomForestClassifier` to predict alert severity from sensor features, replacing the firmware's hardcoded frequency thresholds with a data-driven model.

## Prerequisites

- Python 3.10+
- pip

## Setup

```bash
cd ml
pip install -r requirements.txt
```

## Workflow

### 1 — Generate synthetic training data

```bash
python generate_data.py
```

Creates `training_data.csv` with 2000 labeled samples. Features include peak frequency, signal amplitude, GPS coordinates, hour of day, frequency variance, and recent alert rate.

### 2 — Train the model

```bash
python train.py
```

Expected output:
```

  Train: 1600  Test: 400
```

Saves `model.pkl`, `scaler.pkl`, and `model_meta.json`.

### 3 — Start the Flask service

```bash
python app.py
```

Runs on `http://0.0.0.0:5001`.

### 4 — Verify

```bash
curl http://localhost:5001/health
```

Expected:
```json
{ "status": "ok", "modelLoaded": true, "accuracy": "XX.X%" }
```

Test a prediction:
```bash
curl -X POST http://localhost:5001/predict \
  -H "Content-Type: application/json" \
  -d '{
    "peakFrequency": 1450,
    "amplitude": 0.82,
    "lat": 38.9072,
    "lng": -77.0369,
    "hourOfDay": 14,
    "frequencyVariance": 230.5,
    "alertsLastHour": 5
  }'
```

## API

### `POST /predict`

| Field | Type | Description |
|-------|------|-------------|
| `peakFrequency` | float | FFT peak in Hz (50–2500) |
| `amplitude` | float | Signal strength (0.0–1.0) |
| `lat` | float | Sensor GPS latitude |
| `lng` | float | Sensor GPS longitude |
| `hourOfDay` | int | UTC hour 0–23 |
| `frequencyVariance` | float | Variance across last 5 readings |
| `alertsLastHour` | int | Alerts sent by this node in last hour |

`regionRiskScore` is derived internally from `lat`/`lng`.

Response:
```json
{
  "predictedSeverity": "high",
  "confidence": 0.87,
  "featureBreakdown": {
    "frequencyRisk": "high",
    "regionRisk": "standard",
    "behaviorRisk": "elevated"
  },
  "modelInfo": "RandomForestClassifier trained on simulated data..."
}
```

### `GET /health`

```json
{ "status": "ok", "modelLoaded": true, "accuracy": "89.5%" }
```

## Notes on model quality

The model is currently trained on **synthetic data** generated by `generate_data.py`. The severity labels are derived from the same feature rules used by the firmware, plus Gaussian noise, which means:

- The model learns approximately the same logic as the thresholds but is not a perfect replica
- Confidence scores are meaningful but not calibrated to real failure rates
- **Accuracy will improve significantly once real alert data from deployed hardware is collected**

### Retraining with real data

Once the hardware is deployed and MongoDB contains real alerts, export the data:

```bash
mongoexport --db voltvigil --collection alerts --type csv \
  --fields peakFrequency,amplitude,lat,lng,hourOfDay,frequencyVariance,alertsLastHour,severity \
  --out real_training_data.csv
```

Update `train.py` to load `real_training_data.csv` instead of `training_data.csv`, then retrain:

```bash
python train.py
```

The running Flask service will pick up the new `model.pkl` on next restart.
